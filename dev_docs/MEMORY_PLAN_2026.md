# 记忆系统计划 2026 —— 面向 SillyTavern 的四层记忆

> **状态：设计稿（未实现）。**
> 本文不改变任何现有行为，也不是 `ARCHITECTURE.md` 的替代。
> 它的用途是：在动手之前，把"哪些结论可以直接执行"和"哪些只是有道理但风险未知"分开。

---

## 0. 适用范围：三个项目的目的不同，结论不能直接搬运

| 项目 | 目的 | 运行环境 | 能给我们什么 | **不能**给我们什么 |
|---|---|---|---|---|
| **Aetheria Unified Memory（本项目）** | 让 SillyTavern 的长程 RP 记忆**又省又稳** | 单进程浏览器扩展；无后端；共享一段 prompt 预算；provider 不可假设 | —— | —— |
| **AIRP** (`D:\all_the_airp`) | 一个**独立的 agent 化叙事平台**：事件溯源 SQLite、Director/Character 双 lane、工具调用、可重启回放、分支 | 有宿主、有数据库、有工具边界 | 记忆的**架构原则**（派生投影、证据链、隔离语义） | 依赖平台的能力：显式场景事件、工具边界、多 lane 调度 |
| **ai_model_training** (`D:\ai_model_training`) | **训练** 20M/100M 小模型，把昂贵计算固化为廉价通路 | PyTorch，改权重 | 记忆的**认知压缩原则**（只存差异、schema+deviation）与研究方法论 | 任何需要改权重/训练的手段 |

**据此划定三条硬约束（本文所有设计都不得违反）：**

1. **不能依赖工具调用。** provider 不保证模型会调工具；AIRP 自己实测过"模型选了错的工具然后瞎猜"。凡是要靠模型主动检索的，只能当补充。
2. **不能依赖显式事件边界。** 酒馆没有导演，没有 `scene/ended`。AIRP 的 `13` 号文自己记录了"导演从不发 end_scene，记忆一开始根本没触发"。
3. **不能改权重。** 一切"内化/睡眠重放/微调"都超出插件能力范围。

## 1. 目标（验收标准来自使用者，不是功能清单）

原始要求：**高优质压缩 / 宏观上记忆强 / 关键事物不遗忘 / 大部分细节有所掌握 / 不丢失记忆逻辑。**

拆成 **3 个不变量 + 2 个成本约束**：

| 编号 | 要求 | 不变量/约束 | 负责机制 |
|---|---|---|---|
| I1 | 关键事物不遗忘 | **不矛盾**：canonical 永不被后来的总结覆盖 | Fact 层 + supersede 链 |
| I2 | 不丢失记忆逻辑 | **不迷路**：因果/时序脊完整 | Spine 层 |
| I3 | 大部分细节有所掌握 | **可追问**：细节按需可取，不常驻 | Detail 指针层 |
| C1 | 高优质压缩 | 成本约束 A：常驻体积与层数不成正比 | Schema 层 + 重复度驱动压缩 |
| C2 | 宏观上记忆强 | 成本约束 B：观感 | 注入配比 |

**可测判据（替代"读起来连贯"）：**

> **T-Causal**：给一个只读记忆、不读原文的读者，问「为什么现在会是这样？」「这件事谁先做的？」「谁还不知道？」。
> 答对率就是"逻辑有没有丢"的分数。

## 2. 统一执行名单（S 级）

**入选标准（全部满足才进名单）：**
① 直接服务于 I1–I3 中的至少一个；② 不依赖 LLM 判断，或依赖极小；③ 能在离线测试里写成断言；④ 失败不污染已有数据（可回滚/只增不改）；⑤ 不引入新的 provider 能力或网络依赖。

| ID | 名称 | 来源 | 做什么 | **验收（可测）** | 风险 |
|---|---|---|---|---|---|
| **S1** | 确定性逻辑脊 Spine | AIRP append-only+lineage；训练项目 Δ | 每次抽取后由**代码**追加事件节点 `{seq, msg_range, participants, slot_changes[], supersedes[], caused_by[]}`，几乎不含散文 | 单测：节点数 == 抽取出的事件数；`spineTrace(fact_id)` 能枚举该事实的全部变更点 | 无（纯追加） |
| **S2** | supersede 边一等公民 | AIRP supersession | 把 supersede 从 memory 记录的附属字段提升为 Spine 的一等边，并保留旧值快照 | 单测：任意 slot 可枚举完整历史；`m_4_0 → m_6_0`、`m_8_1 → m_14_0` 这类链必须被断言 | 无 |
| **S3** | 消除 summary→summary 链 | AIRP「原始事件永远不能被后来的摘要覆盖」 | L2/L3 的生成本源改为**原始 turn/message 区间**，不再是 L1 的 text | 断言：`level2[].source_ids` 中不含 `summary_l1_` 前缀；扰动测试——改一条 L1 不改变 L2 | 中低（可回滚；不改则违反 I1） |
| **S4** | 不可逆性排序 + 永不丢集合 | 本文推导（kind 语义） | 给 kind 定不可逆等级：`commitment > identity/relation > ownership > knowledge > state`；前四类与**所有 supersede 边**进入 `never_drop`，不受任何预算裁剪 | 压力测试：注入 500 条噪声记忆后 `never_drop` 集合仍完整、不被裁剪 | 低 |
| **S5** | 首次发生无条件保留 | 训练项目自我修正（"单次事件没有 deviation ≠ 没有信息"） | `first_occurrence` 标记，永久保留 | 单测：同一事件首次实例永不被压缩掉 | 无 |
| **S6** | provenance 通道规范化 | AIRP provenance；训练项目「Perception ≠ Recollection ≠ Description」 | 每条记忆记录取得通道（`saw / heard / told / inferred`）+ 来源指针；现已有 `source_message`，补"通道" | 单测：任何记忆都能回答"我是怎么知道的" | 低 |
| **S7** | **对照实验：强制基线 vs 召回池** | AIRP `08` 号文的 50/50 实证 | **一次性验证项，不是功能**：同一条关键事实，A 组强制进必带基线，B 组只进召回池，比较使用率 | 产出结果表：A/B 命中率；结论决定后续 rerank/graph/prefetch 的投入方向 | 低（只读实验） |
| **S8** | 确定性 delta ledger | 训练项目 `Memory = Observation − Prediction` | 每轮追加一条无散文的增量记录（哪些 slot 变了）；它是 S1 的输入，也是"压缩率随重复度上升"的前提 | 断言：ledger 体积/层数为常数级 | 无 |

**执行顺序建议：S1 → S2 → S8 → S7 → S4 → S5 → S6 → S3。**
理由：S1/S2/S8 是无风险的纯增量；S7 是决策实验，做完才知道 S3 之后的优先级；S3 是唯一会改动既有产物（摘要树）的一项，放最后。

## 3. 自行设计部分（A 级：有道理，但风险未验证）

> 这一节是**我的设计**，不是从两个项目搬来的结论。每项都标注了不确定性与降级方案。

### A1 层级从"同种不同分辨率"改为"不同种类"

**问题诊断**：现有 `L1/L2/L3` 是**同一种东西的三个分辨率**，这使重叠不可避免，也使 L2 引用 L1 成为结构性必然（不是实现失误）。人脑层级差在 **kind**，不在 **length**。

**设计**：四层载体（详见 §5 数据模型）

| 层 | 存什么 | 生成方式 | 可否丢 |
|---|---|---|---|
| ① Spine | 事件节点 + 因果边 + supersede 边 | 确定性代码 | 永不 |
| ② Fact | slot → 当前值 + 覆盖链 | 确定性 | 值可覆盖，链永不 |
| ③ Schema | "通常怎样" + 出现次数 + 代表实例 + 偏离 | 归并（默认关闭） | 可丢、可重构 |
| ④ Detail | 原始楼层区间指针 | 已存在 | 内容可丢，指针留到闸值 |

**不确定性**：中。**降级**：即使 ③ 永远不启用，①②④ 也能独立成立。

### A2 边界检测（替代 `scene/ended`）

酒馆没有导演，所以要自己推边界。三段判据：

1. **硬边界**：地点或参与者集合发生变化（可从 slot 推导，纯确定性）
2. **软边界**：发生**不可逆变更**（承诺 / 身份 / 关系 / 所有权）
3. **兜底**：楼层节拍（保留现有"每 10 层"，但降级为 fallback 而非主判据）

**不确定性**：高。**降级**：任一判据失效即退回楼层节拍——永远不会比现在更差。

### A3 Schema 归纳（**默认关闭**）

这恰好是训练项目列出的两个真正未解难题（"什么时候两个事件属于同一个 `At`"、"什么时候 `At` 该分裂"）。**保守规则**：

- 归并条件：同一 kind 序列 + 同一参与者集合出现 **≥3 次**，且期间**无不可逆变更**
- 分裂条件：只允许在**不可逆变更**或**硬边界**处分裂
- 宁可归并过度，也不要过早分裂（分裂错了是永久噪声）

**不确定性**：高。**降级**：默认关闭，只在离线评测集里验证。

### A4 重复度驱动压缩率

压缩预算 = `f(重复度)`，而非常数。现在的压缩率是恒定的（10 层 → ~190 token，实测），这是"按部就班"最贵的代价。重复越多，压缩率应越高（`chat_6` 的 schema+deviation）。

### A5 注入配比

必带基线（Fact 当前值 + Spine 摘要 + 未闭合线索）与可选召回（Detail）的配比。现有硬顶：`reference_context_max_chars: 12000` + `current_state_context_max_chars: 5000`。**配比需要实测，不预设。**

### A6 遗忘按"可重构性"

> 凡是能从 Spine + Schema 重构出来的，都可以丢；凡是不能重构的，永不丢。

- 可从 schema + 指针重构 → 可丢
- 承诺 / 谜题 / 身份 / 首次发生 → 不可重构 → 永不丢

### A7 存储布局

新增层一律进 **derived store**（不进聊天文件），延续 iteration 13 的既定方向。**注意**：派生键必须保持内存可读，只用 `toJSON` 过滤序列化——把派生键从 live store 剥离会静默打断所有读者（已踩过）。

### A8 度量

新增四个指标，全部可离线计算：

| 指标 | 定义 |
|---|---|
| 关键保留率 | `never_drop` 集合在任意压力下的完整率 |
| 因果问答正确率 | T-Causal 的分数 |
| 压缩率 | 常驻记忆 token / 原始对话 token，按层数画曲线（判断是否恒定） |
| 注入增量 | 新增层带来的 prompt token 净增量 |

## 5. 数据模型草案

```
spine_node   { id, seq, msg_range:[a,b], participants[], slot_changes[], supersedes[], caused_by[], first_occurrence }
fact         { slot, value, since_seq, history:[{value, at_seq, superseded_by}] , never_drop:bool }
schema       { id, signature, occurrences, representative_seq, deviations[], state:'proposed'|'active' }
detail_ptr   { memory_id, msg_range, expiry:null|seq }
provenance   { memory_id, channel:'saw'|'heard'|'told'|'inferred', source_message, evidence_excerpt }
```

**体积估算**（按实测 token 模型 `0.9408×CJK + 0.2441×other`）：

| 记录 | 估算 |
|---|---|
| spine_node | ~20–40 token（无散文） |
| fact | ~10–30 token |
| schema | ~40–80 token（每条代表整个模式集） |
| detail_ptr | ~5 token |
| 现有 L1 摘要（对比基线） | 实测 173 / 205 token |

即：**逻辑脊的成本约为一条 L1 摘要的 1/6，但它是唯一能回答"为什么现在这样"的层。**

## 7. 未解决问题（诚实记录）

1. **事件切分没有成熟方案**（A2/A3）。三家都没解决：AIRP 靠导演，训练项目列为开放问题，我们靠楼层节拍。这是最大的不确定性。
2. **"压缩率随重复度上升"尚未验证**。理论上成立，但没有实测数据。
3. **L2 的代价未测**。S3 改成从原始证据生成，会提高单次总结的输入长度；成本增量未测。
4. **Schema 归并的失败模式未知**。错误的归并会把两个不同的事件混成一个模式，且不可逆。
5. **`never_drop` 集合的长期增长未评估**。如果它线性增长，"关键不遗忘"和"高压缩"最终会冲突，需要回收策略（但回收策略本身可能违反 I1）。

## 8. 落地修正记录（S 级实施后）

### 8.1 S5 的语义修正

- **计划原文**："首次发生无条件保留"——首现记忆进入必带基线，与承诺/所有权同等待遇。
- **实测事实**：本插件里"首次发生"按 slot 计算，而 slot 几乎每条唯一。实机 43 条记忆里 **41 条都是首现**，真正的不可逆记忆只有 4 条。
- **照做会怎样**：必带基线变成 41 条，每轮强塞进提示词，压缩比（每 10 层 1,098 token）直接崩掉——违反 C1。
- **实际实现**：`first_occurrence` 照记（在 spine 的 `first_by_slot` 里可查"这个槽位第一次出现在第几层"），但**不作为必带入选判据**；仅在必带集合内部做排序加权。它真正的用途是留给 **A3 schema 归并**——那时首现要免于被归并掉，而 A3 尚未实现。
- **坦诚结论**：**S5 是八项里实机实效最弱的一项，目前"只记不用"。**

### 8.2 spine 的存储位置决定

- **计划原文（A7）**：新增层一律进 derived store，不进聊天文件。
- **实测**：把 `spine` 注册进 `DERIVED_KEYS` 后，实机 `store.spine` **恒为 undefined**——直接写单测能拿到，从插件 store 读就读不到。S4 的必带基线、S2 的变更链、S6 的 provenance 每轮都要读它，等于全废。
- **根因**：一旦该聊天存在外部派生记录，`setExternallyOwnedKeys(DERIVED_KEYS)` 会使 chat_metadata 的 setter 把每一个派生键**从运行时读者看到的那个 store 对象上删掉**。代码里的 `toJSON` 过滤只保护"尚无外部记录"的一半情况。
- **修正**（本轮已实施）：
  1. 所有权守卫的语义从"删除"改为"**不复活**"——写入方产出的派生键保留在内存中，只拒绝把写入方省略的键从旧值里复活；
  2. 派生存储把序列化过滤器**注册**进守卫（`setStoreSerializationFilter`），使每个新生成的 store 对象都带过滤，而不只是 `persistChatStore` 经手的那些；
  3. `spine` 重新登记为派生键。
- **结果**：spine 既离开聊天文件，又对运行时读者可见；聊天文件仍不含任何派生键。
- **代价**：本轮曾一度把 spine 作为"权威但有界"（300 节点上限）放进聊天文件，产生 15.6 KB / 51 节点。修正后这部分体积回到外部记录。

### 8.3 一句话更正

`派生键对运行时读者不可见` 与既有的 `cold_turns 到不了外部记录` 是**同类症状**，但因果链**尚未证明**（`queueDerivedWrite` 拿到的是剥离前的对象，理论上仍能写出）。该问题继续列为开放项，不计入本轮成果。

## 附：本文与两个参考项目的关系

- AIRP：提供**架构原则**（派生投影、证据链、隔离语义、禁止 summary→summary）。本项目不实现它的平台能力。
- ai_model_training：提供**认知压缩原则**（只存差异、schema+deviation、provenance）与**研究方法论**（预注册门槛、批次一致性、失败即结论）。本项目不采用它的任何训练手段。
- 两个项目都不能替代 T-Causal 验收：**它们的原则只有在我们自己的数据上复现，才算数。**
