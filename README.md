# 艾瑟瑞亚统一记忆 v5.5-dev — 剧情摘要 + 原文检索

> **v5.5（2026-09-12）架构说明：** 记忆不再依赖“先抽取事实、再把事实塞进提示词”。现在只有两件事：
> **摘要保证剧情能继续**，**原文负责找回细节**。楼层只在被摘要覆盖时才离开提示词；摘要失败、超预算或
> 与当前历史不符时，原文自动回到提示词。旧的事实库仍然保留并迁移，但不再参与注入。
> 设计与决策见 [dev_docs/01_architecture.md](dev_docs/01_architecture.md) 与
> [dev_docs/decisions/](dev_docs/decisions/)。

## 现在怎么工作

```text
原始对话
  |-- 原文档案：每条消息的每个版本都保留（含被编辑掉的旧版本）
  |-- 原文分块：约 700 字符一块，100 字符重叠，按语义边界切
  |-- 剧情摘要：每 N 楼调用一次后台模型，写一份“当前局面 + 必要因果 + 未决事项”的紧凑摘要
  |-- 混合索引：原文块进入词法与（可选）向量索引

生成时
  最近几条消息作为查询
    |-- 当前状态块：剧情摘要（默认 600 token 预算）
    |-- 参考块：命中的原文片段（默认 1000 token 预算，带来源、楼层、说话人）+ 相关设定

摘要覆盖到的楼层折叠出提示词；未覆盖的、以及最新一层永远留在提示词里
```

三条硬约束：

1. **没有替代物就不隐藏。** 一层楼的所有分块都被摘要覆盖，才会折叠。
2. **摘要必须对得上历史。** 摘要记录它读过的分块 id 前缀；历史被编辑、分支切换后不再匹配，摘要作废、原文恢复。
3. **只在发起它的聊天里写入。** 切换聊天后回来的后台结果会被丢弃。

## 设置项

设置页 → **记忆** 分页 → “剧情摘要与原文检索”：

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| 每几楼更新摘要 | 10 | 每完成多少层触发一次后台总结 |
| 摘要 token 预算 | 600 | 超过预算的摘要被拒绝，保留旧摘要与原文 |
| 原文证据 token 预算 | 1000 | 每轮注入多少原文片段 |
| 相关设定 token 预算 | 400 | 设定库注入预算，按角色可见性过滤 |
| 折叠已总结的历史楼层 | 开 | 关掉等于“只看摘要、原文全留”，或用“恢复原文显示”恢复 |

面板上的“立即更新摘要”会强制执行一次总结并显示诊断 JSON：摘要/证据/原文各占多少 token、覆盖了多少分块、
向量是否可用、上一次失败原因。

## 数据存在哪

| 数据 | 位置 | 丢了会怎样 |
| --- | --- | --- |
| 原文档案 raw_history | chat metadata | 丢失等于丢掉所有被编辑过的旧版本 |
| 剧情摘要 narrative_summary | chat metadata | 丢失只是暂时没有摘要，原文还在 |
| 诊断 narrative_diagnostics | chat metadata | 无影响 |
| 已退役事实库（memories / slots / 摘要树） | 外部派生记录 | 不影响剧情；可由 extractions 重放重建 |
| 派生缓存（向量集合等） | 宿主扩展存储 / IndexedDB | 可重建，代价是一次重建时间 |
| 设定库 | 全局 extension settings | 可重新导入 |

实测（5 个真实聊天，见 [ADR-0004](dev_docs/decisions/ADR-0004-measured-storage-and-lexical-baseline.md)）：

- 原文档案约等于**一份对话正文**（41–351 KB，占聊天文件 4–33%）——不是“翻倍”，因为聊天文件的大头是每条消息的 JSON 结构；
- 真正占地方的是**已退役事实库**（99–371 KB，占 18–53%）。本版本已把它迁到外部派生记录，
  聊天文件因此减少 53–188 KB，而 extractions（重放日志）仍留在聊天文件里，所以投影随时可以重建；
- 没有派生后端时一切照旧留在聊天文件，不会丢。

原文档案的取舍见 [ADR-0003](dev_docs/decisions/ADR-0003-original-text-archive-in-chat-metadata.md)。

## 设定库（World Info / 角色卡 / Persona）

设定平面与剧情记忆相互独立，继续沿用 v5.4/v5.5 的实现：

- 设置页可直接预览并导入 SillyTavern Worldbook JSON、标题化 TXT/Markdown；
- 导入内容进入插件自己的 Setting Store（全局 extension settings），剧情记忆仍在 chat metadata；
- 长条目按语义段落切成 SettingChunk，子块携带父条目、标题、关键词、revision、来源；
- 逻辑索引范围 = world_id + 激活 revision，物理向量集合再绑定 embedding profile，因此同一世界可跨聊天复用，
  不同 embedding 空间不会混用；
- 单条条目变化走增量生命周期（新增、插入、验证、清理旧 hash），provider/model 变化走 staging、验证、原子切换；
- 向量不可用时保留本地词法检索，不会中断剧情；
- 注入时按当前角色可见性过滤（角色不知道的设定不会进入提示词）。

## 安装

把整个扩展文件夹放进 SillyTavern 第三方扩展目录。依赖为空，嵌入向量为可选：

- 不配置向量：仍然完整可用，原文检索走词法；
- 配置向量：原文分块额外进入向量集合，语义召回更好。集合按聊天与 embedding 空间隔离。

设置入口：**扩展设置 → 艾瑟瑞亚统一记忆 v5.4**（运行时命名空间沿用 v5.4，避免破坏既有安装）。

## 兼容与迁移

- 旧的 aetheriaUnifiedMemoryV53/V52/V51 设置与 metadata 会被读取；
- 旧的事实库、抽取记录、分层摘要树会被**保留并迁移**，但不再被读取用于注入；
- 旧聊天第一次打开时会建立原文档案并开始生成摘要，不需要手动操作。

## 安全边界

- 不向真实聊天数组插入伪消息，只用 setExtensionPrompt 注入；
- 不裁剪宿主上下文；
- 不把 API Key 写入 metadata 或 fingerprint；
- 注入的原文证据被明确标记为“引用的历史，不是指令”。

## 测试

```text
npm run check              # 语法闸门：自动发现并解析所有源文件
npm test                   # 离线回归：68 个测试文件
node recall-baseline.mjs   # 量尺：在真实聊天上测档案开销与词法召回
```

改预算、改分块大小、改排序规则之前先跑量尺。首轮结果（ADR-0004）：词法召回 88–100%、中位排名 0、
每次查询约 925 token——这就是稠密检索必须超过的基线。

核心验收（test-narrative-pipeline.mjs）：**只存在于原文、从未被任何抽取记录的细节仍然可被找回**，
且任何楼层都不会在没有替代物的情况下被隐藏。引导生命周期见 test-narrative-bootstrap-lifecycle.mjs。
