# 艾瑟瑞亚剧情记忆

SillyTavern / TauriTavern 扩展：**摘要保障剧情续接，原文检索找回细节。**

## 工作方式

1. 原文按消息版本存入聊天 metadata，编辑后的旧版本保留。
2. 每 **10 个已完成 user turns** 自动总结一次，通常对应 **20 个消息楼层**；角色开场白不计入。
3. 总结产生剧情摘要、连续性锚点和知情边界。历史被编辑时三者共同失效。
4. 已被有效摘要完整覆盖的历史楼层才会折叠；最新一轮与未总结原文仍保留。
5. 生成时，最近三条消息查询原文分块，经过 BM25、可选向量融合和可选重排，按预算引用原文。

摘要不是向量入库文本。向量索引的是“说话人 + 原文分块”。普通生成读取已提交的剧情状态，
不会触发或等待总结；后台总结成功后才提交替代状态。总结失败、被截断或超预算时保留旧状态和原文。

## 默认预算与设置

| 设置 | 默认值 |
| --- | --- |
| 总结间隔 | 10 个已完成 user turns |
| 剧情摘要 | 600 token |
| 连续性锚点 | 300 token |
| 知情边界 | 200 token |
| 原文证据 | 1000 token |
| 相关设定 | 400 token |
| 重排 | 未配置模型时关闭 |

预算是各块内容上限，标题另有开销；宿主未总结原文不在这些预算之内。锚点记录仍生效的承诺、
所有权等约束；知情边界记录谁知道什么。它们帮助模型遵守剧情，但不是强制隔离机制。

设置页的记忆分页提供总结间隔、预算、立即总结和恢复原文。诊断显示已完成 user turns、
待总结数量、覆盖分块、证据来源与总结响应指标；旧诊断里的 floors 字段兼容保留，单位见 cadence_unit。

## 总结连接

优先使用宿主 ChatCompletionService 或所选连接 profile，保留原始响应中的 finish_reason、
正文长度与 usage。只记录推理长度和用量，不保存推理正文。返回 length/max_tokens 时拒绝提交残缺状态。

DeepSeek 总结请求默认关闭推理，使用请求内参数，不修改主聊天设置。高级设置
narrative_summary_thinking=inherit 可保留连接原有推理行为。其他模型沿用连接行为。
缺少原始响应接口的旧宿主回退到 generateRaw / generateQuietPrompt，此时部分响应指标不可用。

## 安装与数据

将扩展目录安装到宿主第三方扩展目录。入口为 index-v55-bootstrap.js，保留 v5.4 设置命名空间以兼容旧安装。
不配置向量时使用词法检索。原文档案和剧情状态跟随聊天；向量索引可重建；设定库保留独立的导入、
版本、索引和可见性过滤。旧事实数据只用于兼容迁移，不再参与剧情注入。

原文档案保留已观察到的消息版本，不承诺恢复插件启用前已经丢失的文本。聊天文件会随原文增长。
